Performance playbook

Measure first. Fix the biggest bottleneck. Measure again.

Workflow: how to attack any slow page
  1. Reproduce with throttling (CPU 4x, Slow 4G) and a production build.
  2. Classify: slow load (network, bundle), slow interaction (main thread, re-renders), or layout shift.
  3. Measure: Lighthouse and DevTools Performance for load, React Profiler for renders, Network waterfall for requests.
  4. Fix the largest cost, one change at a time.
  5. Verify with before/after numbers. Write them down.

Loading and bundle size
  • Code-split by route and by heavy component: React.lazy + Suspense, or import() on interaction.
  • Analyze the bundle (vite-bundle-visualizer, @next/bundle-analyzer). Look for moment, lodash, big icon packs, duplicate deps.
  • Import narrowly: import debounce from "lodash/debounce", or use a small native alternative. Keep tree-shaking working (ESM, sideEffects: false).
  • Preconnect to critical origins, preload critical fonts (font-display: swap), use modulepreload.
  • Images: AVIF/WebP, srcset/sizes, loading="lazy" below the fold, explicit dimensions.
  • Cache: hashed assets with Cache-Control: public, max-age=31536000, immutable; HTML with no-cache or short TTL.
  • Third-party scripts: load with async/defer, or after interaction. Audit them regularly.

Rendering: stop wasted re-renders
  • Colocate state as low as possible. Most re-render problems vanish here.
  • Lift content up: pass expensive subtrees as children so a state change in the parent doesn't re-create them.
  • memo only on components that are expensive and re-render with equal props. It needs stable props.
  • useMemo/useCallback: for expensive calculations, or to keep identity stable for memo children and effect deps. Not everywhere.
  • Split context by update frequency. Or use a selector-based store (Zustand, useSyncExternalStore) so consumers subscribe to slices.
  • Stable, unique keys. Never array index for reorderable lists.
  • Derive values during render instead of syncing them with useEffect + setState.
  • Check whether the React Compiler is enabled in your stack before hand-memoizing.

Concurrent React: keep input responsive
  • useTransition marks a state update as non-urgent (tab switch, filter) so typing and clicks stay snappy.
  • useDeferredValue lets a slow consumer lag behind a fast value (search input → results).
  • Suspense boundaries around slow parts so the rest of the page renders first.
  • Split long tasks (>50ms): chunk work, scheduler.yield() or setTimeout, Web Workers for CPU-heavy code.

onChange={e => { setInput(e.target.value); startTransition(() => setQuery(e.target.value)); }}
Lists, tables and large data
  • Virtualize beyond a few hundred rows (TanStack Virtual, react-window). Render only what is visible.
  • Paginate or infinite-scroll on the server. Don't ship 10k rows.
  • content-visibility: auto + contain-intrinsic-size to skip rendering offscreen sections cheaply.
  • Debounce search input; cancel stale requests with AbortController.
  • Keep row components small and memoized, with stable callbacks (pass an id, not a new closure per row, where it matters).
Data fetching and caching
  • Use TanStack Query (or similar) for server state: dedupe, cache, background refresh, retries.
  • Avoid request waterfalls: fetch in parallel, prefetch on hover/route intent, hoist fetches to the route level.
  • Tune staleTime to cut refetching; use select to subscribe to slices; optimistic updates for instant feel.
  • HTTP: ETag/conditional requests, compression (br/gzip), HTTP/2+, stale-while-revalidate.
  • Server Components / SSR / streaming: send HTML early, keep client JS small. Mark only interactive parts "use client".
Browser rendering and CSS
  • Animate transform and opacity only. Avoid animating layout properties.
  • Avoid layout thrashing: batch DOM reads then writes.
  • Use contain, will-change sparingly, and passive event listeners for scroll/touch.
  • Inline critical CSS, avoid large CSS-in-JS runtime cost on hot paths, prefer CSS variables for theming.
  • Respect prefers-reduced-motion.
Memory and leaks
  • Clean up effects: listeners, timers, subscriptions, observers, AbortController.
  • Watch for closures retaining big objects, unbounded caches, detached DOM nodes.
  • DevTools → Memory: take heap snapshots before/after an action and compare.

Performance review checklist
  • Production build, throttled CPU and network
  • LCP element identified and prioritized
  • Route-level code splitting in place; bundle analyzed
  • No request waterfalls; data cached
  • State colocated; contexts split; lists virtualized
  • No long tasks over 50ms on key interactions
  • Images sized, modern format, lazy below the fold
  • Fonts preloaded with swap; no layout shifts
  • Third-party scripts audited
  • Before/after numbers recorded

debounce JS 
function debounce(fn, ms) {
  let t;
  return (...a) => { clearTimeout(t); t = setTimeout(() => fn(...a), ms); };
}
throttle JS 
function throttle(fn, ms) {
  let last = 0;
  return (...a) => { const n = Date.now(); if (n - last >= ms) { last = n; fn(...a); } };
}
memoize JS 
function memoize(fn, key = (...a) => JSON.stringify(a)) {
  const c = new Map();
  return (...a) => { const k = key(...a); if (!c.has(k)) c.set(k, fn(...a)); return c.get(k); };
}
Promise.all JS 
function all(ps) {
  return new Promise((res, rej) => {
    const out = []; let n = 0;
    if (!ps.length) return res(out);
    ps.forEach((p, i) => Promise.resolve(p).then(v => { out[i] = v; if (++n === ps.length) res(out); }, rej));
  });
}
Event emitter JS 
function emitter() {
  const m = new Map();
  return {
    on(e, f) { (m.get(e) ?? m.set(e, new Set()).get(e)).add(f); return () => m.get(e).delete(f); },
    emit(e, ...a) { m.get(e)?.forEach(f => f(...a)); },
  };
}
useDebounce hook 
function useDebounce(value, ms = 300) {
  const [v, setV] = useState(value);
  useEffect(() => { const t = setTimeout(() => setV(value), ms); return () => clearTimeout(t); }, [value, ms]);
  return v;
}
useLocalStorage hook 
function useLocalStorage(key, init) {
  const [v, setV] = useState(() => {
    try { const s = localStorage.getItem(key); return s ? JSON.parse(s) : init; } catch { return init; }
  });
  useEffect(() => { localStorage.setItem(key, JSON.stringify(v)); }, [key, v]);
  return [v, setV];
}
useFetch with abort hook 
function useFetch(url) {
  const [s, setS] = useState({ data: null, error: null, loading: true });
  useEffect(() => {
    const ac = new AbortController();
    setS({ data: null, error: null, loading: true });
    fetch(url, { signal: ac.signal })
      .then(r => { if (!r.ok) throw new Error(r.status); return r.json(); })
      .then(data => setS({ data, error: null, loading: false }))
      .catch(error => { if (error.name !== "AbortError") setS({ data: null, error, loading: false }); });
    return () => ac.abort();
  }, [url]);
  return s;
}
useIntersection hook 
function useIntersection(opts) {
  const ref = useRef(null);
  const [seen, setSeen] = useState(false);
  useEffect(() => {
    const el = ref.current; if (!el) return;
    const io = new IntersectionObserver(([e]) => setSeen(e.isIntersecting), opts);
    io.observe(el);
    return () => io.disconnect();
  }, []);
  return [ref, seen];
}
usePrevious hook 
function usePrevious(v) { const r = useRef(); useEffect(() => { r.current = v; }); return r.current; }
Tiny store with useSyncExternalStore state 
function createStore(init) {
  let s = init; const subs = new Set();
  return {
    get: () => s,
    set: p => { s = { ...s, ...(typeof p === "function" ? p(s) : p) }; subs.forEach(f => f()); },
    sub: f => (subs.add(f), () => subs.delete(f)),
  };
}
const useStore = (st, sel = x => x) => useSyncExternalStore(st.sub, () => sel(st.get()));

Rules of the game

  1. Cold start: blank file, timer on, no copying.
  2. Score yourself: done in time, needed hints, or failed. Repeat the last two next week.
  3. Spaced repetition: redo Week 1-4 katas every 2 weeks as 10-minute warm-ups.
  4. Log: one line per session about what tripped you up.
  5. Parking lot: new tools go on a list, reviewed at the end of each phase.
  6. Why over how: principles last, APIs change.
